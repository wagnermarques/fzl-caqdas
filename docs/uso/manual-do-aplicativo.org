* 📘 Escopo deste Manual
Este documento destina-se exclusivamente à **utilização operacional do aplicativo FZL CAQDAS** (instalação, execução, navegação entre telas e fluxo de trabalho na interface).
As anotações de estudo sobre a teoria metodológica de Laurence Bardin e as citações bibliográficas ficam estritamente separadas em [[../teoria/analise-de-conteudo-bardin.org][docs/teoria/analise-de-conteudo-bardin.org]].

* 1. Execução Local e Acesso Online (PWA)

** 1.1 Acesso Web (GitHub Pages)
A aplicação é compilada como Progressive Web App (PWA) e publicada automaticamente em:
- https://wagnermarques.github.io/fzl-caqdas/

** 1.2 Execução em Ambiente de Desenvolvimento Local
Pré-requisitos: Node.js `>= 20` e npm `>= 10`.

#+BEGIN_SRC bash
# Instalar dependências e compilar o monorepo FZL UI
npm install

# Iniciar o servidor de desenvolvimento (porta 3040)
npm run dev

# Gerar build de produção PWA em dist/
npm run build

# Visualizar build de produção localmente
npm run serve
#+END_SRC

* 2. Estrutura de Telas e Módulos do Aplicativo

A navegação principal é feita pelo menu lateral (Drawer) do *FZL AppShell*, organizado em áreas distintas:

** 2.1 Corpus & Materiais
- *Visão Geral (Dashboard)* (`#/`): Exibe contadores de documentos/entrevistas, códigos criados, segmentos codificados e memos registrados, além de atalhos rápidos.
- *Fontes & Documentos* (`#/fontes`): Ambiente completo de gestão do corpus dividido em quatro abas principais:
  1. *Gerenciador de Arquivos (`<fzl-file-manager>`)*: Navegador estilo filesystem com alternância entre Tabela e Grade, pastas hierárquicas (`/entrevistas`, `/documentos`), status de sincronização com a nuvem, leitor embutido (DOCX, Markdown, PDF, TXT) com busca, zoom e botão para envio direto à Área de Codificação. Documentos sincronizados no Google Drive exibem o botão direto **Abrir no Google Docs ↗**.
  2. *Upload & Importação (`<fzl-document-picker>`)*: Ingestão de arquivos Word (`.docx` com leitor nativo OOXML), PDFs, Markdown, TXT e planilhas (CSV/JSON), com suporte a drag & drop, seleção no celular e integração direta com o upload na nuvem.
  3. *Google Drive & Docs*: Painel dedicado de configuração de nuvem onde o pesquisador conecta sua conta pública Google/Microsoft, define a pasta de destino no Google Drive, ativa a conversão automática de DOCX para Google Docs e consulta a lista de links diretos na nuvem.
  4. *Digitação Manual de Transcrição*: Formulário para inserção ou colagem direta de atas e entrevistas.

** 2.2 Análise Qualitativa
- *Área de Codificação* (`#/codificacao`): Selecione um documento, destaque trechos do texto com o cursor do mouse, escolha um código no seletor e clique em **Codificar Trecho** para criar o excerto vinculado.
- *Livro de Códigos (Codebook)* (`#/codebook`): Agrupa os códigos por categoria, exibe a definição operacional, cor identificadora e a frequência de ocorrências em todo o projeto. Permite criar novos códigos.
- *Matriz Comparativa* (`#/comparativo`): Exibe uma tabela cruzada entre **Participantes/Casos** (linhas) e **Códigos** (colunas), mostrando a frequência de menções por informante.
- *Memos & Diário de Bordo* (`#/memos`): Espaço para registrar reflexões analíticas do pesquisador durante a análise dos dados.

** 2.3 Referencial Metodológico (Separado do Manual de Uso)
- *Teoria: Análise de Bardin* (`#/teoria-bardin`): Módulo dedicado ao estudo teórico, fichamento do vídeo/playlist, seleção de fontes acadêmicas de acesso aberto com citações ABNT e caderno de anotações teóricas.

** 2.4 Saídas & Integração
- *Relatórios & Python/Pandas* (`#/relatorios`): Permite baixar todo o projeto em formato ~JSON~ e fornece um script Python pronto para carregar os excertos no Pandas (~pd.DataFrame~) e gerar tabelas cruzadas (~pd.crosstab~).

** 2.5 Ajuda & Operação
- *Documentação do Aplicativo* (`#/documentacao-app`): Guia rápido de operação integrado dentro da própria interface web.

* 3. Armazenamento e Privacidade Local
- Os dados de pesquisa (~fzl_caqdas_research_data_v1~) e as anotações teóricas de estudo (~fzl_caqdas_theory_study_v1~) são persistidos localmente no navegador (~localStorage~), mantendo os dois acervos isolados.
- Recomenda-se utilizar periodicamente a função **Baixar Projeto Completo (JSON)** na tela de Relatórios para backup externo dos seus dados empíricos.

* 4. Login Social com Google e Microsoft e Sincronização no Google Drive & Docs

** 4.1 Login Social com Contas Públicas (`<fzl-social-login>` & AppShell)
O aplicativo adota a arquitetura oficial do *FZL AppShell* com autenticação federada declarativa em ~appshell.config.js~:
- *Google Identity Services (GIS)*: Permite login com qualquer conta Google pública (`@gmail.com`) ou Google Workspace institucional.
- *Microsoft Account & Entra ID*: Permite login com contas públicas da Microsoft (`@outlook.com`, `@hotmail.com`, `@live.com`) e contas corporativas do Office 365 via OAuth2.
- *Configuração Declarativa no AppShell (`appshell.config.js`)*:
  #+BEGIN_SRC javascript
  export default defineAppShellConfig({
    title: 'FZL CAQDAS — Pesquisa Qualitativa',
    socialAuth: {
      enabled: true,
      googleClientId: '',
      microsoftClientId: '',
      microsoftTenantId: 'common',
      requestDriveScope: true,
    },
  })
  #+END_SRC
- *Ativação por Variáveis de Ambiente ou Interface*:
  - No build / CI / GitHub Secrets: ~VITE_APPSHELL_SOCIAL_AUTH_GOOGLE_CLIENT_ID~ e ~VITE_APPSHELL_SOCIAL_AUTH_MICROSOFT_CLIENT_ID~ (ou as variáveis legadas ~VITE_GOOGLE_CLIENT_ID~ e ~VITE_MICROSOFT_CLIENT_ID~).
  - Em tempo de execução no navegador: basta colar seu *Google Cloud Client ID* ou *Microsoft Azure Client ID* na aba **Google Drive & Docs** de Fontes (`#/fontes`); o sistema invoca ~authService.configureSocialAuth()~ atualizando instantaneamente todas as telas do AppShell.
- *Passo a Passo para Obtenção do Google Client ID*:
  1. Acesse o [[https://console.cloud.google.com/apis/credentials][Google Cloud Console]].
  2. Em *Tela de consentimento OAuth*, configure como *Externo*.
  3. Em *Credenciais*, crie um *ID do cliente OAuth* do tipo *Aplicativo da Web*.
  4. Em *Origens JavaScript autorizadas*, insira ~https://wagnermarques.github.io~ (e ~http://localhost:5173~ se rodar localmente).
  5. Copie o Client ID gerado (~...apps.googleusercontent.com~) e cole no aplicativo.
- *Passo a Passo para Obtenção do Microsoft Client ID*:
  1. Acesse o [[https://portal.azure.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade][Portal do Azure (Registros de Aplicativo)]].
  2. Clique em *Novo registro* com suporte a contas pessoais e corporativas.
  3. Adicione a URI de redirecionamento do tipo *SPA*: ~https://wagnermarques.github.io/fzl-caqdas/~ e ~https://wagnermarques.github.io~.
  4. Copie o *ID do aplicativo (cliente)* e cole no aplicativo.
- O acesso pode ser realizado tanto pelo menu lateral em **Login Social** (`#/conta/entrar`) quanto diretamente no painel **Google Drive & Docs** dentro da tela de Fontes (`#/fontes`).

** 4.3 Controladores Reativos Headless e Extensibilidade (`caqdas-controllers.js`)
O CAQDAS estende os novos controllers pré-programados do ecossistema FZL (`@fzl/webcomponents-lit/controllers`):
1. *`CaqdasPersonalCloudDocsController` (estende `FzlPersonalCloudDocsController`)*:
   - Orquestra a autenticação e o envio de arquivos para o **Google Docs / Google Drive** ou **OneDrive**.
   - O hook `onPersonalDocUploaded()` atualiza automaticamente o documento no corpus com a URL externa (`externalViewerUrl`) e o status sincronizado.
   - Fornece o método `syncCorpusDocument(doc)` para envio sob demanda de entrevistas existentes para o Google Docs com 1 clique.
   - Conecta-se diretamente aos web components através de `picker.bindSocialAuth(authCtrl)` e `manager.bindSocialAuth(authCtrl)`.
2. *`CaqdasDocxCodingController` (estende `FzlDocxReaderController`)*:
   - Decompõe arquivos Word e transcrições em **Unidades de Registro (UR)** de Bardin (§1, §2, etc.) através do método `toRegistrationUnits()`.
   - Na Área de Codificação (`#/codificacao`), permite clicar em uma UR para carregar instantaneamente o parágrafo inteiro para vinculação de códigos, além de controle de zoom tipográfico.
3. *`CaqdasBookmarksController` (estende `FzlBookmarksController`)*:
   - Gerencia documentos marcados como prioritários ou favoritos com sincronização em tempo real entre abas (`storage` event).
